# Sprint 02 Retrospective

## Información General

| Campo         | Valor                                              |
| ------------- | -------------------------------------------------- |
| Sprint        | 02                                                 |
| Participantes | Scrum Master, Product Owner y Equipo de Desarrollo |

---

# Objetivo

Reflexionar sobre el desarrollo del Sprint 02 para identificar fortalezas, dificultades y oportunidades de mejora que permitan optimizar el trabajo del equipo en los siguientes sprints.

---

# ¿Qué salió bien?

- Se completaron todas las historias de usuario planificadas.
- El equipo logró implementar correctamente el sistema de autenticación.
- Se adquirieron nuevos conocimientos sobre Server Actions y bases de datos vectoriales.
- La comunicación entre los integrantes mejoró respecto al Sprint anterior.
- La documentación del proyecto se mantuvo actualizada durante el desarrollo.

---

# ¿Qué no salió tan bien?

- Se presentaron conflictos frecuentes al integrar ramas mediante Git.
- Algunos integrantes no pudieron asistir a determinadas reuniones por compromisos académicos.
- La configuración inicial de pgvector tomó más tiempo del estimado.
- Algunas tareas requirieron ser reasignadas debido a la carga de trabajo.

---

# Lecciones Aprendidas

Durante este Sprint el equipo identificó varios aspectos importantes para mejorar su proceso de desarrollo:

- Planificar mejor la distribución de tareas.
- Realizar commits pequeños y frecuentes.
- Integrar cambios al repositorio con mayor regularidad.
- Revisar la documentación oficial antes de implementar nuevas tecnologías.
- Comunicar oportunamente cualquier inconveniente que pueda afectar el avance del Sprint.

---

| Incrementar las pruebas antes de finalizar cada historia       | Equipo de Desarrollo |
| Mantener actualizada la documentación                          | Todo el equipo       |

---

# Aspectos a Mantener

El equipo decidió continuar con las siguientes prácticas:

- Reuniones Daily Scrum.
- Organización mediante Jira.
- Uso de GitHub para el control de versiones.
- Documentación continua del proyecto.
- Comunicación constante entre los integrantes.

---

# Conclusión

El Sprint 02 representó un crecimiento importante tanto para el proyecto como para el equipo de desarrollo. Aunque surgieron algunos desafíos técnicos y organizacionales, estos fueron superados mediante el trabajo colaborativo y la búsqueda de soluciones.

Las experiencias obtenidas servirán para afrontar el Sprint 03 con una mejor organización, mayor conocimiento de las herramientas utilizadas y una planificación más precisa de las tareas.
