# System Roles

The LlegoYa platform is designed to be used by different types of users. 

Each role has specific permissions, responsibilities, and functionalities.

---

# Commuter (User)

## Description

The individual who uses public transportation. These are the people who need and look up information regarding routes and buses.

They represent the primary beneficiary of the system.

---

## Responsibilities

* Query transit routes.
* Search for destinations.
* Interact with the AI assistant.
* Manage personal favorite routes.
* View query history.

---

## Permissions

Can:

* Register / Sign up.
* Log in.
* Edit profile details.
* Search and view routes.
* View live bus locations.
* Save favorite routes.
* Use the smart chat.

Cannot:

* Create routes.
* Create buses.
* Manage drivers.
* Modify operational data.

---

## Use Cases

Examples:

* Searching for a route to get to work.
* Checking for nearby buses.
* Asking the AI which route to take.
* Saving a frequently used route.

---

# Driver

## Description

The person responsible for operating a vehicle belonging to a transit company. 

Their primary function is to feed real-time location data into the system via their mobile device.

---

## Responsibilities

* Share real-time location.
* Check assigned routes.
* Update operational status.
* Maintain up-to-date data.

---

## Permissions

Can:

* Log in.
* View assigned route.
* Share GPS location.
* Change operational status.

Cannot:

* Create routes.
* Create buses.
* Manage users.

---

## Operational Statuses

* Available.
* In Service.
* On Break.
* Out of Service.

---

# Administrator

## Description

The person responsible for managing the operations of a transport company, possessing full privileges to handle administrative tasks.

They have access to management and supervision tools.

---

## Responsibilities

* Manage drivers.
* Manage buses.
* Manage routes.
* Supervise overall operations.

---

## Permissions

Can:

* Create and edit driver profiles.
* Create and edit bus records.
* Create and edit routes.
* Assign drivers/buses to routes.
* Monitor operational information.

---

## Use Cases

* Assigning a driver to a specific bus.
* Creating a new transit route.
* Updating operational information.
* Supervising active vehicles on the map.

---

# Relationship Between Roles

Administrator
↓
Drivers and Buses
↓
Real-Time Geolocation
↓
Commuters (Users)
↓
Queries and AI Interactions

This relationship represents the primary workflow of information across the platform. 

Every operational update generated by administrators and drivers directly benefits the end user by delivering real-time information and intelligent recommendations.
